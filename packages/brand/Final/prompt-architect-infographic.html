02 · The Architect — Four Phases

From messy input to ready-to-run prompt.

The Architect is the core MVP spoke. It walks through four phases: paste raw input, structure it into three pillars, validate with a test run, then export.

2.1.1 — The Dump Zone

Drop raw text here. No format required. Paste an email, a meeting note, a scribble — anything that holds the germ of what you need.

  • Accepts plain text from any source
  • iOS and Android share-sheet compatible
  • No minimum structure required from the user

2.1.2 — Intent Classifier

NLP detection maps pasted content to persona signals, task actions, and format keywords. The output seeds the Triple-Pillar editor.

  • Runs via LLM Gateway in JSON mode
  • Produces a Persona / Task / Format suggestion
  • User can accept, edit, or start from scratch

2.2.1 — Persona Selector

Who is running this prompt? Pick a role or describe your own. Anchors the model's voice and expertise frame.

  • Pre-built role library: writer, analyst, coach, and others
  • Free-text custom persona option
  • Persists as Default Persona in Settings

2.2.2 — Task Definer

What is the prompt trying to do? A single, clear action phrase per task. The most common source of vague outputs.

  • Action-verb-first validation hint shown
  • Suggested task from Intent Classifier pre-filled
  • One task per prompt, by design

2.2.3 — Format Gallery

How should the output look? A card-based visual picker that reduces the cognitive load of the Format pillar.

  • Paragraph, bullet list, table, JSON, email, script
  • Visual card layout, tap to select
  • Custom format via free-text override

2.2.4 — Context Manager

Optional attachments that give the model the background it needs. Constraints, examples, and reference material go here.

  • Free-text context blocks
  • Example input/output pairs
  • Hard constraints on the output

2.3.1 — Split-Screen Simulator

Run the assembled prompt against the selected model. See the raw output alongside the prompt in one view, closing the feedback loop inside the app.

  • SSE streaming — no silent waits on mobile
  • Uses the user's selected provider from Settings
  • Output displayed without reformatting

2.3.2 — Variable Injector

Replace placeholder tokens in the prompt with real values before running. One tap per variable, turning prompts into repeatable templates.

  • Auto-detected from {{variable}} syntax
  • Fill-in form generated at Test Flight time
  • Variables saved with the template in The Vault

2.3.3 — Hallucination Check

A risk score that flags likely confabulation in the output. Requires a second model call — scoped to V2, not in the MVP.

  • Dual-model agreement scoring
  • Risk score displayed alongside output
  • Status: V2 — deferred from MVP scope

2.4.1 — Copy to Clipboard

One tap. The full assembled prompt, ready to paste into any LLM interface the user already uses.

  • Copies the final rendered prompt string
  • Variables replaced with injected values at copy time
  • Available from any point after pillar completion

2.4.2 — Save to Library

Saves to The Vault as a personal template. Title and tags are optional at save time — can be added later.

  • Draft status moves to exported
  • Stored in My Good Stuff (private by default)
  • Forkable as a Community Recipe later

2.4.3 — Share

Deep links that open the prompt in the user's chosen LLM with one tap, ready to run without paste required.

  • ChatGPT, Claude, Gemini deep-link targets
  • Share sheet for mobile native sharing
  • Shareable link to the Vault template
03 · Feature Priority Hierarchy

What ships first, and why.

Features are ordered by user impact and MVP scope. The first two are load-bearing — nothing else matters until they work reliably.

Critical — must ship at launch

Critical
Smart Paste / Intent Classifier — turns raw input into structured pillars without manual typing. Without this, the app is just a form.
Critical
Triple-Pillar Editor — Persona, Task, and Format fields with validation before Test Flight is allowed. This is the product.

High — launch window

High
Smart Start — one-tap guided session for first-time users, bypassing the Dashboard and going straight to The Architect.
High
Visual Format Gallery — card-based format picker that reduces the cognitive load of choosing an output format.
High
Test Flight Simulator — split-screen output view that closes the feedback loop inside the app, not in a separate LLM tab.

Medium — post-launch

Medium
Recent Projects — last five drafts on the Dashboard, with a Resume action. Reduces re-work for returning users.
Medium
Variable Injection — token replacement before Test Flight, turning one-off prompts into repeatable fill-in-the-blanks templates.
Medium
Recipe Book — Community Recipes browseable in The Vault. Requires moderation infrastructure before going public.

V2 — deferred

V2
Hallucination Scorer — risk flag on Test Flight output. Requires a second model call and a scoring methodology that needs human-eval validation first.
V2
Model Toggle — provider selection in Settings, blocked on the LLM Gateway being production-ready. BYOK is Phase 2 per the system design.
04 · Strategic Recommendations

Three decisions that shape the whole product.

These are framing decisions, not features. They affect every surface and must be settled before detailed design begins.

1

MVP Focus: Smart Paste + Triple-Pillar Editor

Phases 2.1 and 2.2 are the product. Without a reliable path from messy input to structured pillars, the rest of the app has nothing to test. Ship these two phases before adding anything else. The Vault only has value when there is something to save.

2

Navigation: bottom tab bar with four destinations

Dashboard, Architect, Library, Settings. Four tabs maps exactly to the four surfaces. Keep the structure flat at launch — no nested navigation until The Vault needs filtering at scale.

3

Onboarding: first launch goes straight to The Architect

A guided session on first open, bypassing the Dashboard entirely. The Dashboard's value depends on prior work existing. Show the Dashboard when there is something to show.
