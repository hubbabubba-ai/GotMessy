✦ Brand Guidelines · v1.0 · Operational rules

Apply Got Messy
without breaking it.

The kit tells you what the brand is. This tells you how to use it — and where not to. Wordmark rules, accent budgets, accessibility floors, voice antipatterns, motion timings.

Extends Brand Identity Kit. If anything here contradicts the kit, the kit wins.

01 · Wordmark & Logo Usage

The wordmark is one mark, not three pieces

Italic got, bold Messy, and the clay dot are a single typographic lockup. Treat them as one element when sizing, spacing, and animating.

Reserve clear space equal to the cap-height of "M" in Messy. Below the minimums, switch to the icon mark — don't shrink the wordmark.

03 · Accessibility

Accessibility is brand

A messy-friendly product that's hostile to readers is off-brand. WCAG 2.2 AA is the floor, AAA where achievable.

PairRatioUse
--cream on --ink~14.7:1AAA · default body
--dust on --ink~6.3:1AA · labels & metadata only
--clay on --ink~4.6:1AA · large text & UI components only — not body
--clay-lt on --ink~6.9:1AA · preferred for interactive accents
--ink on --warm~13.5:1AAA · light-mode default

Required behaviours

Visible focus on every interactive element. Use outline:2px solid var(--clay-lt); outline-offset:2px. Never outline:none without a replacement indicator.

44×44px minimum touch targets on mobile. The product is mobile-first.

Honour prefers-reduced-motion: reduce. The blinking sage live-dot must freeze at 100% opacity.

Forms & images

Never use placeholder text as a label.

Every logo/icon image needs meaningful alt text. Decorative chrome is alt="" or aria-hidden="true".

Re-validate contrast every time a token hex changes. The colour sheet is the source — regenerate the table here.

04 · Typography in Practice

Italic Lora is seasoning, not the dish

Lora for serif (display, headings, the wordmark, italic emphasis). Poppins for sans (body, UI, eyebrows). The kit covers families; this covers the application scale.

LevelFamily / weight / styleSizeUse
DisplayLora 700, italic on accent wordsclamp(3rem, 7vw, 5.5rem)Hero only — once per page
H1Lora 7002.25remPage title
H2Lora 7001.5remSection heading
H3Lora 6001.15remSub-section
EyebrowPoppins 600, uppercase, +0.06em tracking0.72remAbove H1 / section labels
BodyPoppins 300–4000.875–1remDefault copy
CaptionPoppins 3000.75remTimestamps, helpers

Use italics for: the word "Got" in the wordmark; one emphasised noun per heading; pull quotes. Don't italicise long body passages.

Numerals that stack (pricing, dashboards, the Hub stats grid) use font-variant-numeric: tabular-nums.

Body line length: 60–75 characters. Constrain prose blocks with max-width: ~620px.

Brilliant friend. Not a tutor, robot, or coach.

The kit's personality line operationalised. The pairs below are the load-bearing ones.

Always

Forbidden vocabulary

Tone by surface

SurfaceToneExample
OnboardingWarm, concrete, confident"First thing — drop something messy in. Anything."

Punctuation

Em dashes — yes. Exclamation marks — almost never (max one per page, only when the user shipped). Emoji — sparing, flat, used as section markers (🪞, 🧬, ✦), not body decoration.

07 · Domains & Naming

One consumer brand. One held alias.

gotmessy.com Lead

The only consumer-facing domain. Marketing, product, docs all live under it.

cloudcomb.com Held

Reserved for the enterprise / team edition. Don't link from gotmessy.com until that product launches. Don't borrow Cloud Comb's orderly tone — the contrast is the point.

Product feature names use Title Case — The Architect, The Drop, Mirror It, My Good Stuff, User DNA, The Vault. Internal codenames (MirrorMind, Intent2Flow) are fine in technical docs but should not surface in UI.

08 · Asset Versioning

Working copy → -final → ship

Per CLAUDE.md, every asset has a working copy and a -final canonical variant. The -final file is what ships.

  1. Drop the working file (no suffix) into Final/.
  2. Once approved, copy it to its -final counterpart and update the matching PDF where one exists.
  3. Re-run contrast / legibility checks if a token changed.
  4. If the asset replaces a canonical file, capture the why in the commit message — terse history is no longer acceptable for design changes.
